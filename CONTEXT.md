# HTMLPatterns — Context Glossary

Pattern-based HTML element selection and text extraction for the Wolfram Language. Operates on the static `XMLObject` tree produced by `Import[…, {"HTML", "XMLObject"}]`.

This file is a glossary, not a spec. It defines the language we use to talk about the domain. Implementation lives in the code; decisions live in `docs/adr/`.

**Audience**: people working on the repository. The terms here are for code, tests, ADRs and design discussion; they are not the vocabulary of what users see. User-facing text — documentation pages, `::usage` strings and messages — is written in plain language for its reader, and uses a term from here only when the reader needs the concept, defining it on first use. An _Avoid_ entry governs internal discussion and does not rule out the plain word in user-facing text: the pages say "attributes", not "attribute map". Internal names (private functions, helpers, comments) may use the glossary freely.

**Naming convention** (not a domain term, but load-bearing for reading the glossary): a symbol reading a (near-)canonical property off the tree is named `HTML‹Noun›` — "the ‹noun› of the tree." A symbol performing a directed, lossy, opinionated projection — where there is no canonical answer — is named `‹X›To‹Y›`, signaling "expect loss, do not expect a round-trip."

## Language

### Text extraction

**HTMLTextContent**: The lossless concatenation of every descendant text node, in document order, with no whitespace inserted or removed. The DOM `textContent` analogue. _Avoid_: HTMLText (former name through v1.0.2), text content, raw text

**HTMLInnerText**: Text as the structural meaning of the tags implies it should read: whitespace collapsed, block tags on their own line, `<br>` as a newline, preformatted tags verbatim, non-rendered tags dropped (a non-rendered element passed in gives its whole text, trimmed). The DOM `innerText` analogue, approximated via the [[Frozen UA stylesheet]] since a non-rendered element has no layout to consult. _Avoid_: rendered text, visible text, display text

**Block separator**: The single global string (default `"\n"`) inserted between Block boundaries when `HTMLInnerText` emits text — the `get_text(separator=…)` analogue. Uniform across all tags; never varies per tag. _Avoid_: line separator, join string

### Display role

**Display role**: The per-element classification that drives readable-text extraction: **Block**, **Inline**, **Preformatted**, **LineBreak**, or **Skip**. Assigned by the [[Frozen UA stylesheet]] table or a [[Role rule]]. _Avoid_: display type, tag category, render mode

**Box**: The axis of a display role distinguishing **Block** (own line) from **Inline** (flows with neighbors). Decided fresh at every element; not inherited. _Avoid_: layout axis

**Whitespace mode**: The axis of a display role distinguishing **Normal** (whitespace runs collapse to one space) from **Preserve** (verbatim). Inherited down the tree, unlike [[Box]]. _Avoid_: whitespace handling

**Frozen UA stylesheet**: Our fixed tag → rendering table, snapshotting the WHATWG HTML §15 default user-agent stylesheet. Never consults per-page CSS — not classes, `<style>`, external sheets, or inline `style=`. Drives both [[Display role]] and default [[Construct]] assignment; both are [[Tags-only]]. _Avoid_: default stylesheet, UA CSS

**Role rule**: A user-supplied override (`HTMLInnerText`'s `"Roles"` option) of the form `key -> role`, whose key is an element test or a query (see [[Assignment arrow]]) and whose role is one of five flat tokens (`"Block"`, `"Inline"`, `"Preformatted"`, `"LineBreak"`, `"Skip"`). Tried in order, the first that selects an element wins; unmatched elements fall through to the [[Frozen UA stylesheet]]. _Avoid_: role override, classifier

**Tags-only**: The standing rule that display roles and constructs are decided from the tag name alone, never from `class` or inline `style=`. Predictable; tags-plus-CSS is not. _Avoid_: tag-based, CSS-aware

### Selection

**XML pattern**: The paclet's third kind of pattern, beside WL's patterns and string patterns: what the XML* functions and the [[Role rule]] and [[Construct rule]] options take as a pattern. It is a [[Pattern root]] with what is below it: `XMLPattern[tag, attrs][c…]` with its [[Constraint]]s in the second bracket, nested as the document is; an `XMLElement` pattern, with its literal WL meaning; `XMLDocument[c…]`; and `Alternatives`, `Condition`, `PatternTest` and naming over these. A [[CSS selector]] string, where an XML pattern is accepted, is one too, and a [[One-element selector]] string takes constraints in the same way: `"ul.c"[c…]`. `MatchQ` and `Cases` treat it as a literal expression, as `MatchQ` treats a string pattern. It reads as an ordinary WL pattern at every level: `XMLPattern`'s `tag` and `attrs` are WL patterns (`attrs` is what `KeyValuePattern` takes, keys are literal and values are matched as written), a list constraint is a WL list pattern, a name bound only in an alternative that did not match is `Sequence[]`, and a `Condition` sees only the names bound inside the pattern it wraps; a test relating names in different places goes on a pattern that contains them. It departs from WL in three places: a literal string at a [[List key]] means "contains this token"; a name in two [[Constraint]]s of one `XMLPattern` names one place, so it compares positions, not values; and a [[Query]] gives one [[Result]] per distinct tuple of positions of its [[Counted name]]s, not one per match. _Avoid_: selector

**Pattern root**: The top of an [[XML pattern]]: an `XMLPattern`, an `XMLElement` pattern, an `XMLDocument` pattern, a one-element CSS string, or alternatives of these, any of them conditioned, tested or named. A pattern describes its pattern root and what is below it, never what is above; context above an element is written by rooting the pattern higher. Always qualified: the bare word "root" is the document's root element. _Avoid_: root (alone), anchor (retired: it had two meanings), subject (CSS's implicit result, which XML patterns do not have), top

**Constraint**: An argument of the second bracket of `XMLPattern[tag, attrs][c…]`, or of `XMLDocument[c…]`, saying what is below the element: a WL list pattern over its element children, text not listed; `Child[p]`, some element child matching `p`, the same as `{___, p, ___}`; `Descendant[p, levelspec]`, some element strictly below matching `p` at a [[DOM depth]] in the level spec; or alternatives of constraints. All of an element's constraints must hold, each independently, except that a name in two of them names one place. Several constraints are the arguments of one bracket, never `p[a][b]`. A constraint is not a pattern: `Child` and `Descendant` stand nowhere else, and a negated constraint is a test with `XMLFreeQ`. _Avoid_: children argument, stage, relation

**Element pattern**: An [[XML pattern]] whose [[Pattern root]] is an element, not the [[Document]]: an `XMLPattern` or `XMLElement` pattern, alternatives of element patterns, or either conditioned, tested (`pat?f`) or named. [[Constraint]]s only look down, so every element pattern can be tested on an element alone, as `XMLMatchQ` and the element-test keys of the [[Role rule]] and [[Construct rule]] options do. _Avoid_: selector, XMLElement pattern (that is the literal kind)

**CSS selector**: A string in the static Selectors Level 4 dialect (literal case, no namespaces, no soupsieve extensions) that `FromCSSSelector` translates into an [[XML pattern]], and that the XML* functions and the [[Role rule]] and [[Construct rule]] options accept wherever an XML pattern goes, meaning its translation. A [[One-element selector]] translates to a pattern; a [[Context selector]] translates only once its subject is named, `FromCSSSelector[n : s]`. The translation is literal, against the imported tree, so it matches what the importer put there. It is a way to write an XML pattern, not a fourth kind of pattern: a CSS selector says nothing its translation does not. _Avoid_: selector (alone), CSS pattern, CSS query

**One-element selector**: A [[CSS selector]] that looks only at its subject and what is below it, so its subject is its [[Pattern root]]: one compound, downward `:has()`, `:not()`/`:is()`/`:where()` over compounds, or a list of these. Precisely: `n : FromCSSSelector[s]` and `FromCSSSelector[n : s]` agree. It is an [[Element pattern]]. _Avoid_: simple selector (CSS's word for one part of a compound), compound selector

**Context selector**: A [[CSS selector]] that picks its subject by what is above or beside it: combinators, child-indexed pseudo-classes, `:root`, `:scope`, `:has(+ …)`, `:has(~ …)`, complex `:not()`/`:is()`/`:where()`, or a list holding one. It is a pattern only once its subject is named, and `FromCSSSelector` never invents that name; consumers that accept it unnamed name the subject themselves, out of sight. _Avoid_: complex selector (CSS's word, which includes some one-element selectors), combinator selector

**Selector list**: A [[CSS selector]] of several selectors separated by commas, selecting what any of them selects. It translates to one pattern over [[XML pattern]] alternatives that share the subject's name, so it gives the union of their subjects, each once. _Avoid_: selector group, union (the general feature, not the CSS form)

**Top element**: An element with no element parent inside the tree a query is given: the root element of an `XMLObject` document, a bare `XMLElement` input itself, or each top-level element of a list. A query sees nothing outside its input, so there is no root above a top element. A bare `XMLElement` input is never itself a result, as `Cases` never returns level 0: its own [[Position]] is never counted. Every other top element's can be, and so can the [[Document]]'s. _Avoid_: root (alone; it can mean the input or a document's root element), document element

**Document**: The parent of the [[Top element]]s, which every input has: the `XMLObject` for a document input, the list for a list input, and a virtual parent above a bare `XMLElement` input. Its [[Position]] is `{}`. It is matched only by an `XMLDocument[c…]` [[Pattern root]], whose contents list lists the top elements, so a list input's top elements are siblings and a document's root element is an only child. _Avoid_: document node, scope, scoping root (the input, which differs from the document for a bare element)

**Document order**: The order things open in the source. For elements: an element before the elements nested in it, an earlier sibling (and its subtree) before a later one — the DOM's tree order, a pre-order walk. For [[Position]]s: by where each starts in the source, and on a tie the one that contains the other first, so an element comes before its tag, attributes, contents and children. For [[Result]]s: a nested loop over the [[Counted name]]s in the order they appear in the pattern, the first name slowest, each in document order; `XMLFirstCase` gives the first. Not WL's `Cases` order, which puts an element after the elements nested in it. _Avoid_: source order, Cases order

**Query**: What an XML* function is given to select by: a rule `pattern :> rhs` or `pattern -> rhs` over an [[XML pattern]], giving one [[Result]] per distinct tuple of positions of its [[Counted name]]s. A bare pattern `p` is first erased to `r$ : p :> r$`, so it gives its matches as `Cases` does. A [[CSS selector]] string is a query wherever an XML pattern is. _Avoid_: selector, search

**Result**: One entry of the list `XMLCases` returns, given by one distinct tuple of [[Position]]s of a [[Query]]'s [[Counted name]]s. Equal values at different positions are different results. With no counted names there is one empty tuple, so at most one result. _Avoid_: match (a pattern can match in many ways that give one result), body, subject, hit

**Counted name**: A name a [[Query]]'s right-hand side uses, outside the tests of `Condition`s: the names whose positions set the [[Result]]s. In `XMLReplace`'s targets form only the left sides of the target rules count. An uncounted name, and an unnamed part, is a test that needs one passing match. _Avoid_: result name, selected name, target

**Query arrow**: The `:>` or `->` of a rule given to `XMLCases`, `XMLFirstCase`, `XMLPosition`, `XMLDeleteCases` or `XMLReplace`: its left side is a pattern and its right side says what each [[Result]] gives or acts on. A query arrow never has a rule on its left. _Avoid_: body arrow, rule (alone, when the kind matters)

**Assignment arrow**: The `->` or `:>` of a [[Role rule]] or [[Construct rule]], `key -> value`. Its key is an element test (an [[Element pattern]], each element tested as its [[Pattern root]]) or a query (a rule, whose counted element positions get the value). _Avoid_: role arrow, override

**Named pattern**: `Pattern[x, p]`, written `x : p` or `x_`, as in WL: a pattern given a **name**, the symbol `x`, by which a `Condition` or a rule's right-hand side refers to what it matched. _Avoid_: named part, binding, variable

**Position**: Where in the tree a [[Named pattern]] matched: the [[Document]], an element, an element's tag, attribute map or contents, one attribute's value, a [[Token list]] or one token, run of tokens or gap between tokens in it, a run of sibling elements, or the gap between two siblings, where an empty run matched, or a [[Path]]. Written as a list of element-child indices from the document, with at most one terminal step: `{1, 2}` is the second element child of the root, `{1, 2, Key["href"]}` its `href`, `{1, 2 ;; 1}` the gap before it. A path is written by its two ends, `{1} ;; {1, 2, 1}`, and stands for the elements strictly between them. Text is not a position, as in CSS: it is reached through its element. Elements are counted among element children only. Two equal values at different positions are two positions. _Avoid_: site, binding site, location, part (WL part specifications count text and the `XMLElement` slots), path (a [[Path]] is something else)

**Path**: The elements strictly between an element and one of its descendants, outermost first: empty for a child. It is how a pattern states context between the two, such as "no `nav` above" or "no table in between": `p : Descendant[…]` names the path from the [[Pattern root]] to the match, and `Descendant[…]?test` tests it. Fixed by its two ends, so one per pair, and counting it counts both ends. _Avoid_: ancestors (only when the upper end is the document), chain, route

**Compiled query**: A [[Query]] as the compiler leaves it, under the [[Reading]]s in force: each element pattern made an ordinary WL pattern, together with how each part runs. Computed from the query alone, never from the tree. _Avoid_: normal form, plan, matcher

**Solution table**: The ways one part of a [[Compiled query]] matches the whole input, held as columns: one row per solution, one or more packed integer columns per name the part keeps, mostly of [[Place code]]s, beside the column of the node where its pattern root matched. Every operation of matching is an operation on tables: a tag test filters rows, `Descendant` joins a table against the subtrees of another's roots, `Alternatives` is a union, and the [[Result]]s are the distinct rows over the [[Counted name]]s, sorted. _Avoid_: solution set, bindings, frame

**Place code**: A place on an element as one integer, ordered as [[Position]]s are: the element's preorder number times a fixed base, plus 0 for the element, 1 for its tag, 2 for its [[Attribute map]] and 2 + j for its j-th attribute's value; the [[Document]] is 0, and -1 is a name a row leaves unbound. Two equal codes are one position, so distinct tuples of positions are distinct rows of integers, and [[Document order]] is integer order. A place that is not on one element, such as a run of siblings, a token or a contents item, has a code below -1 from its [[Owner]] and its indices there, and a [[Path]] one from its two ends. So has a match with no single place: a set of places a name compared by value binds, or a part of a value, as a name in `{ns_, t_}` on a namespaced tag binds; and so has a label, what a walk assumed about the names an `Except` refers to, which no result reads. Such a code sorts by its position only when results are ordered. _Avoid_: position code, slot id

**Owner**: The element, or the [[Document]], whose items one list is matched over: its element children for a list constraint, its contents, text included, for an `XMLElement` pattern's contents list, its tokens for a [[Token list]]. A list is matched at all its owners at once, their items laid end to end. _Avoid_: parent (an owner of a token list is the element itself)

**Attribute map**: The map from an element's attribute names to their values: each name at most once, every value an opaque string. Attribute order is kept but carries no meaning. A **structural** collection: it is present in the tree as itself, and an [[XML pattern]] matches against it directly; a question about the whole map (such as "has some `data-*` attribute") is asked by binding it. An `Association` in spirit, with two differences: the tree holds it as a list of `key -> value` rules, and key order does not count towards equality. Any structure inside a value is a [[Microsyntax]], layered above the markup. _Avoid_: attribute set (drops the one-value-per-name guarantee), attribute list, attributes

**Token list**: The collection obtained by splitting a single attribute's value on a [[Delimiter]]. A **derived** collection: it exists only because we read a string that way, and an [[XML pattern]] reaches it through a [[List key]], never through the raw attribute. An ordinary WL list of strings, matched by ordinary list patterns and list predicates; its order is positional to a pattern, and order-free questions use `MemberQ`, `ContainsAll` and the like. _Avoid_: token set, split value, word list

**List key**: The name under which an [[XML pattern]] reaches a [[Token list]]: `classList` for `class`, by default the raw key with `List` appended, after the DOM's `classList` and `relList`. Exists only for keys with a [[Reading]], and reads as the empty list when the raw attribute is absent. The raw key keeps meaning the raw string, so `"class" -> "menu"` is an exact match and `"classList" -> "menu"` asks for a token; a literal string, or alternatives of them, at a list key means "contains this token", since it could never match a list as written. A key of the form `k <> "List"` that is not a list key in force is matched as an attribute of that name, with a warning on `XMLPattern`. _Avoid_: synthetic key, virtual attribute

**Class list**: The [[Token list]] of an element's `class` attribute, reached as `classList` in a pattern and returned by `HTMLClassList`. A missing `class`, `class=""` and a whitespace-only `class` all give the empty class list, as in a browser; whether the attribute itself is present is a separate question, asked of `class`. Keeps duplicate tokens (`class="lead lead promo"` gives three) because the document does: the DOM stores the attribute value with its duplicates, and only a browser's `classList` view deduplicates, on read. The class list therefore diverges from `classList`, not from the document. _Avoid_: class attribute, classes

**Microsyntax**: A convention for splitting an attribute value into a [[Token list]] — space-separated or comma-separated. **Key-independent**: `class`, `rel`, `headers`, `ping` and `itemprop` all share the space-separated one. _Avoid_: format, syntax, separator convention

**Reading**: A [[Microsyntax]] together with a fixed attribute key and a [[List key]] — what makes a token list available to an [[XML pattern]] at all. Adding a reading adds a key and, with the default list key, never changes what an existing key means; an explicit list key naming a real attribute takes that name over, by the caller's choice. The class reading is the only one that ships by default (in `$AttributeReadings`); `rel`, `headers`, `ping` and `itemprop` share its microsyntax in HTML but carry no reading unless a caller adds one, globally or per query through the consumers' `"AttributeReadings"` option. Matching a reading is written with its list key (`"classList" -> …`); extracting it has its own function (`HTMLClassList` for the class reading). _Avoid_: shorthand, alias, named microsyntax (a reading fixes the key too)

**Delimiter**: The string pattern a [[Token list]] is split on. Distinct from the [[Microsyntax]] that selects it, which also fixes whether tokens are trimmed. The space-separated one is named `HTMLWhitespace`, and it is a **run** of one or more HTML ASCII whitespace characters — mirroring WL's `Whitespace`, not `WhitespaceCharacter`, so that splitting on it never yields a phantom empty token. It is narrower than WL's Unicode default, which splits on no-break space and six other characters HTML does not. _Avoid_: separator (that is the [[Block separator]], a different thing entirely)

### Notebook conversion

**HTMLToNotebook**: A directed, lossy projection of an HTML/XML tree into a `Notebook[…]` expression: each Block [[Display role]] element becomes a `Cell`, each Inline element becomes a box inside the surrounding `TextData`. Markdown, PDF, RTF, and display fall out downstream via `Export`. _Avoid_: notebook export, HTML rendering

**Construct**: What an element becomes in the notebook, chosen after its [[Display role]] places it as block-or-inline. A **block construct** is an open-ended cell-style string (`"Text"`, `"Section"`, `"Item"`, …); an **inline construct** is one of a closed set of box-transform tokens (`"Bold"`, `"Italic"`, `"Underline"`, `"StrikeThrough"`, `"Code"`, `"Hyperlink"`, `"Plain"`). _Avoid_: cell style, render form

**Leaf-collapsing construct**: A construct (`<blockquote>`, `<pre>`, `<table>`) that collapses its whole subtree into a single cell's content rather than recursing into separate child cells. Contrasts with the default recurse-and-flatten behavior of most Block constructs. _Avoid_: table construct (too narrow — also covers blockquote/pre)

**Construct rule**: A user override of the default [[Construct]] map — the Layer-2 analogue of a [[Role rule]] — of the form `key -> construct`, its key as a [[Role rule]]'s, tried in order, the first that selects an element wins. The RHS is a block cell-style string, an inline token, or a constructor function; the [[Display role]] still decides block-vs-inline and wins on conflict. _Avoid_: construct override

### Tree drawing

**HTMLToTree**: A directed, lossy projection of an HTML/XML tree into a `Tree` for display: one node per element and text string, with parts collapsed or removed by the focus, hide and depth settings. _Avoid_: DOM tree, tree view, TreeForm (the WL function it is modelled on)

**DOM depth**: How many generations of elements lie between an element and the element counting starts from: its children are at depth 1, its grandchildren at depth 2. Counting starts at the nearest [[Focused element]] above it, or at the tree's root when there is no focus. With a focus, an element outside every focused element has no depth: it is collapsed, or drawn only because it is on the path to one. Text has the depth of its element. `HTMLToTree[tree, n]` draws elements down to depth *n*. _Avoid_: level (a child element is two WL levels down, at part `{3, i}`), depth alone (WL's `Depth` counts levels)

**Cut element**: A drawn element at the [[DOM depth]] limit that has element children. Its contents are not drawn, except for any [[Focused element]] in them and the path to it: the rest become [[Collapsed run]]s. _Avoid_: truncated element

**Focused element**: An element the `"Focus"` query selects, unless it is a [[Hidden element]] or inside one. It is drawn with its contents below it. _Avoid_: shown element, selected element

**Hidden element**: An element the `"Hide"` query selects, or one in a run it selects. It is removed with its contents and leaves no mark in the tree. Hide can also select an element's contents, text included, which removes them and keeps the element. Hiding wins over focus. _Avoid_: removed, deleted, skipped (Skip is a [[Display role]])

**Collapsed edge**: A dashed edge from a [[Focused element]] to its nearest drawn ancestor. It stands for the path of undrawn elements between them, which `"CollapsePaths" -> False` draws instead. _Avoid_: collapsed chain, elided edge

**Collapsed run**: Consecutive siblings that are not drawn and contain no [[Focused element]]. They are drawn as one [[Collapsed leaf]], in their place in [[Document order]]. _Avoid_: dropped subtree

**Collapsed leaf**: A `…` leaf standing for *n* undrawn elements, with the data `Missing["Collapsed", n]`. It is how a [[Collapsed run]] is drawn, whether outside any focused element or inside a [[Cut element]]. _Avoid_: ellipsis node, placeholder, marker, elided (that is `MaxDisplayedChildren`'s "N total" node)

**Merged text leaf**: The single text leaf that replaces an element's contents when they hold at least one element and every element in them is Inline. Its text comes from [[HTMLInnerText]] or [[HTMLTextContent]]. The element keeps its own node. _Avoid_: flattened text, inline run
